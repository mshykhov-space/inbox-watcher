# Контракт документации

## Роли файлов

- Корневой `README.md`: назначение, запуск, env, доставка и обслуживание конфигурации агентов.
- `docs/README.md`: карта документов, типы и соответствие изменений кода документам.
- `docs/ARCHITECTURE.md`: текущие компоненты, потоки, состояние, внешние границы и инварианты.
- Тематические `docs/*.md`: точный контракт или повторяемая процедура, как Telegram-формат и SQLite-диагностика.
- `docs/setup/README.md`: индекс настройки; `docs/setup/gmail.md`: внешний setup сервиса.

## Имена, язык и ссылки

- Сохраняй существующие пути; новые тематические файлы называй в `kebab-case.md`.
- `README.md` служит индексом, `SCHEMA.md` задаёт правила, `ARCHITECTURE.md` сохраняет существующее имя.
- Пиши по-русски, команды и идентификаторы оставляй на языке реализации; используй обычный дефис.
- В начале документа указывай понятный заголовок и назначение. Обязательного YAML frontmatter нет.
- Ссылки на файлы делай Markdown-ссылками относительно текущего документа, включая ссылки из таблиц.
- Ссылки должны работать из checkout; личные абсолютные пути не используй как навигацию.
- Каждый документ должен быть доступен из `docs/README.md`; подраздел с несколькими темами получает свой индекс.

## Живые документы и срезы

- Живой документ описывает текущий контракт и меняется в том же изменении, что соответствующий код.
- Для будущего среза используй имя `YYYY-MM-DD-topic.md`, указывай дату, статус и проверенный commit.
- Срезы сохраняют выводы на момент проверки; новое решение заменяет прежнее отдельным документом со ссылкой.
- План остаётся живым, пока активен; после завершения фиксирует результат и проверку.
- Не создавай пустые темы, неподтверждённые процедуры или заявления о текущем production.

## Приоритет и проверка

- Код, конфигурация и воспроизводимые проверки определяют реализованное поведение; расхождения исправляй в живом документе.
- Решения и требования могут задавать целевое поведение; явно отделяй его от уже реализованного.
- Состояние развёртывания подтверждается внешней средой; локальный commit и исторический handoff его не доказывают.
- Общие инструкции агентов принадлежат `.rulesync/`; generated outputs воспроизводятся из этого источника.
- При правках сверяй названия компонентов, env и команды с файлами, указанными в карте документации.
- Проверяй изменённые относительные ссылки напрямую; отдельный Markdown test suite не требуется.
