# Канон Telegram-уведомлений

Формат пуша и правила Bot API. Реализация: `telegram/TelegramNotifier.kt`. Разошлось с кодом = баг документации.

## Шаблон

```
❗🗓 <b>Приглашение на интервью · Acme</b>
➡️ <b>Выберите время интервью</b>
{summary - одно предложение по-русски, ≤20 слов}
<blockquote expandable><b>{subject}</b>
{очищенный текст письма, ≤500 симв}…</blockquote>
<a href="{PUBLIC_BASE_URL}/open/{threadId}">Open</a> · <a href="{from-search-link}">Similar</a>
```

Без `PUBLIC_BASE_URL` ссылка Open ведёт напрямую на `{thread-link}` (Gmail web).

Unclassified (деградация классификатора, письмо не потеряно): вместо заголовка -
`⚠️ <b>Письмо не классифицировано</b>` + строка From (единственный оставшийся сигнал).

Строка `➡️` выводится только когда классификатор извлёк конкретный следующий шаг:
`Выберите время интервью`, `Ответьте на вопросы рекрутёра`, `Пройдите тест до пятницы`.
Она не выводится у application receipt/review promise, отказа, уже принятого календарного
инвайта, подтверждённого интервью без RSVP и других писем, где пользователю ничего делать не надо.
`urgency` управляет только маркером `❗` и не создаёт действие автоматически.

## Заголовок

`{❗ если urgent}{иконка типа} <b>{метка типа} · {company}</b>` - company извлекает LLM (пустая -> без хвоста).

| category | иконка | метка |
|---|---|---|
| recruiter-interview-request | 🗓 | Приглашение на интервью |
| recruiter-rejection | ❌ | Отказ |
| recruiter-generic | ✉️ | Письмо рекрутёра |
| personal | 💬 | Личное письмо |
| ai-news | 🤖 | AI-анонс |
| transactional | 🧾 | Транзакция |
| other (important-автоматика: оффер/дедлайн-шаг) | 📌 | Требуется действие |

## Принципы (каждый - ответ на реальный фейл)

1. **Content-first.** Заголовок = тип+компания, затем опциональное конкретное действие и саммари. Саммари сообщает факт и не повторяет действие или обещание «мы рассмотрим резюме». Это превью пуша на локскрине. Служебные шапки IMPORTANT/URGENT/category занимали превью, информации не несли.
2. **Тема - первой строкой цитаты жирным.** Под заголовком курсивом она сливалась с шапкой.
3. **Тело письма - в expandable blockquote.** Читается прямо в Telegram (обход ненадёжных Gmail-линков). HTML-only письма (квитанции, маркетинг) сводятся к плоскому тексту jsoup'ом ещё на ingest (`gmail/GmailClient.kt`) - иначе сырой markup течёт и в цитату, и в промпт классификатора. Чистка перед вставкой: reply-trail отрезается (маркеры `____`, `Від:/From:/Sent:`, `-- `), `<url>`-дубли plain-text писем выпиливаются, whitespace схлопывается, обрезка 500 симв + `…`.
4. **HTML parse mode, не MarkdownV2** (там экранирование 18 символов). В HTML экранируются только `& < >` - обязательно во всех подстановках: `From` почти всегда содержит `Name <addr>`, без экранирования Telegram отвечает 400 и уведомление молча теряется (нарушение zero-miss).
5. **Ссылки анкорами, превью выключено.** Основная - Open через `/open/{threadId}` (страница сама выбирает приложение или веб по устройству; без `PUBLIC_BASE_URL` - напрямую `#all/{threadId}`: Gmail роутит треды, messageId reply-письма ведёт мимо). Запасная Similar - `#search/from:{адрес отправителя}` (на телефоне прямой веб-линк открывает голый инбокс - мобильный веб-Gmail теряет `#`-фрагмент, а по отправителю письмо легко найти руками; поиск по rfc822msgid этого не давал). Веб-линки пинят аккаунт query-параметром `?authuser={email}` - email в слоте `/u/` рисует "Temporary Error", а голый `/u/0/` в мульти-логин браузере открывает чужой профиль. Адрес ящика сервис берёт из Gmail `users/me/profile` на старте (fail-safe -> `/u/0/` без authuser).
6. **Эмодзи = семантика.** `❗` только при urgency=urgent, `⚠️` только у unclassified,
   `➡️` отмечает явную строку действия. Один `❗` оказался недостаточно понятным сигналом.
7. **Секретов в тексте нет.** Промпт запрещает коды/OTP/пароли в summary (пуш виден на локскрине).
8. **Лимиты.** Telegram 4096 симв; с цитатой ≤500 запас большой.

## Мобильный deep-link

Telegram открывает http-ссылки в браузере, и мобильный веб-Gmail теряет `#`-фрагмент - открывается инбокс, не письмо. Universal links для mail.google.com сломаны на стороне Google (AASA редиректит на www.google.com, где 404), а не-http схемы Bot API отклоняет. Обход - линк Open: публичная страница `/open/{threadId}` сервиса (env `PUBLIC_BASE_URL`), которая на телефоне прыгает в недокументированную схему `googlegmail:///cv={threadId}` с кнопкой-fallback на веб, а десктопный браузер уводит сразу на Gmail web. Одна ссылка покрывает оба устройства. Саммари+цитата остаются основным каналом чтения.
